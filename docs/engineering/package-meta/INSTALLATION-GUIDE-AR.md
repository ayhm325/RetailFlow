# دليل تثبيت RetailFlow AI Operating System

## الهدف
هذه الحزمة جاهزة للمراجعة ثم الدمج في مستودع RetailFlow. لم يتم تعديل GitHub أو إنشاء فرع أو رفع أي ملف أثناء إعدادها.

## 1. طريقة التثبيت المقترحة
1. افتح نسخة محلية نظيفة/محدّثة من `ayhm325/RetailFlow`.
2. تحقق من `git status` وأن ملفاتك المحلية غير المعدلة محفوظة.
3. أنشئ فرعاً مستقلاً بموافقتك، مثال:
   `docs/ai-operating-system-v1`
4. انسخ محتويات مجلد الحزمة إلى جذر المستودع مع الحفاظ على المسارات.
5. لا تستبدل ملفات موجودة دون مراجعة. عند وجود تعارض، قارن المحتوى وادمج يدوياً.
6. شغّل:
   `python tools/validate_operating_memory.py`
7. افتح Antigravity على جذر المستودع (وليس مجلد فرعي) وتحقق من ظهور Rules وSkills.
8. شغّل مهارة `start-session` واطلب منها قراءة الحالة فقط دون تعديل.
9. راجع النتائج، ثم اعتمد الملفات عبر PR بعد مراجعتك.

## 2. ما الذي يتم تحميله تلقائياً؟
- `AGENTS.md`: تعليمات جذرية مستمرة.
- `.agents/rules/*.md`: قواعد Antigravity وفق `trigger`.
- `.agents/skills/<name>/SKILL.md`: مهارات إجرائية تُكتشف وتُحمّل عند الصلة أو الاستدعاء.
- `.github/copilot-instructions.md`: تعليمات GitHub Copilot.
- `CLAUDE.md`: سياق Claude Code.
- `GEMINI.md`: مدخل Antigravity إضافي متوافق؛ المحتوى يحيل إلى AGENTS.md.

لا يعني وجود الملفات أن العميل ينفذها كضمان آلي. يجب فحص لوحة Customizations/Skills في إصدار العميل المستخدم، وتشغيل اختبار قبول عملي.

## 3. اختبار قبول العميل بعد التثبيت
اطلب منه:
- قراءة الحالة الحالية والتحقق من SHA الفعلي.
- بيان الفرق بين Product Host وPoCs.
- عرض أعلى 3 مهام نشطة من سجل العمل.
- تحديد حالة AUTH-ADR-01 دون ترقية Proposed إلى Accepted.
- عدم تعديل أي ملف.
إذا أخفق، افحص اكتشاف القواعد/المهارات أو قلّل/صحّح ملفات التعليمات.

## 4. ما لا تفعله الحزمة
- لا تثبّت نفسها تلقائياً في المستودع.
- لا تنشئ Branch/Commit/PR ولا تدفع إلى GitHub.
- لا تشغّل Build/Tests أو Deploy.
- لا تمنح العميل صلاحيات GitHub أو أسراراً.
- لا تجعل تحديث السجلات حتمياً؛ لذلك توجد مراجعة بشرية وCI validation كحواجز إضافية.
